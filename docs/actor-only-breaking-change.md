# Actor-Only Runtime Breaking Change

> Historical SDK note: this document records the earlier migration. References
> to `BotOperationClient` or schema-1 input contracts describe the retired SDK;
> see the [current modular SDK migration](architecture/modular-bot-sdk-migration.md) for schema 2.

Applies to: OBCX C++26 reflected-actor cutover

Date: 2026-07-30

## Supported contract

OBCX now has one extension contract:

- actor libraries inherit `ReflectedActor<Derived>`;
- public direct `handle` overloads return `ActorResult` or
  `ActorTask<ActorResult>`;
- libraries export the ABI 2 symbols generated by
  `OBCX_ACTOR_EXPORT_V2`;
- every library exports a generated schema-1 `obcx_get_actor_contract`;
- receive, typed emit, contracts, and configuration use the fully qualified
  reflected C++ message name;
- packages use one canonical `actor.toml` and `OBCXActor.cmake`;
- runtime flow is declared with `[actors]` and `[pipelines]`;
- the native work-stealing scheduler is always used.

The installed SDK, runtime loader, configuration parser, build system, and
registry expose only that contract.

The admitted build baseline is GCC 16.1+ on Linux x86_64 or arm64 with
`-std=c++26 -freflection` and `__cpp_impl_reflection >= 202506L`. There is no
C++20, Clang, short-name, or hand-written dispatch fallback.

## Removed contracts

This release removes `IPlugin`, `PluginManager`, plugin lifecycle callbacks,
`OBCX_PLUGIN_EXPORT`, `OBCXPlugin.cmake`, plugin reload, `[plugins]`,
`plugins.toml`, and `plugin.toml`.

The operator command named `reload` is supported, but it is a new ABI 2 actor
generation transaction. It does not discover old metadata, invoke removed
lifecycle callbacks, or provide compatibility behavior. It prepares a complete
actor generation, gates root ingress, drains admitted work, atomically swaps
the generation, and retires old libraries only after their final tracked route
reference is released.

It also removes the V1 `IActor` ABI and factories, `AsioActorV1Adapter`,
`allow_v1_actors`, the `asio-v1` scheduler, and actor engine selection.

Bot-owned scheduling is removed as well. `TaskScheduler`,
`IBot::get_task_scheduler()`, and `IBot::run_heavy_task()` no longer exist,
and there is no compatibility forwarding method. A bot supplies transport
capabilities only; synchronous blocking or CPU-heavy work is a runtime actor
concern.

Old binaries and metadata do not load. The actor-only binary contains no
detector, translator, warning branch, adapter, or in-process fallback for
those inputs. An unrelated TOML table receives only the configuration
loader's generic behavior; it is not treated as a migration input.

## Required package changes

1. Inherit `ReflectedActor<Derived>` and declare `actor_name` and
   `actor_version` constants.
2. Replace `handle_message` string switches with public direct `handle`
   overloads whose exact parameters are `(const Message&,
   const MessageEnvelope&, ActorContext&)`.
3. Return `ActorResult` for synchronous work or `ActorTask<ActorResult>` for
   asynchronous work. Move synchronous blocking/CPU work behind
   `ActorContext::run_blocking`; move asynchronous I/O behind
   `ActorContext::await_asio` or `ActorContext::asio_token`.
4. Provide nlohmann ADL JSON conversion for each input and typed output.
5. Export the class with `OBCX_ACTOR_EXPORT_V2`; do not hand-write the input
   contract.
6. Add complete canonical `actor.toml` metadata including the C++26,
   GCC/reflection, and input-contract compatibility fields.
7. Build with `find_package(obcx-sdk CONFIG REQUIRED)`, `include(OBCXActor)`,
   and `obcx_add_actor(...)`.
8. Use fully qualified message names in pipeline configuration and explicit
   `after` edges for dependency ordering.
9. Build and test against a clean OBCX SDK installation before publishing.

The canonical package example is `local_actor/obcx-actor-template`; bridge and
message-store are conformance-tested examples of larger packages.

## Blocking-work migration

Replace bot-coupled calls:

```cpp
auto value = co_await bot.run_heavy_task([repository, query] {
  return repository->fetch_context(query);
});
```

with the actor-facing runtime API:

```cpp
auto value = co_await context.run_blocking([repository, query] {
  return repository->fetch_context(query);
});
```

Code already inside a generation-tracked `context.await_asio(...)` coroutine
may resolve `BlockingExecutor` from the context before entering that coroutine
and use `co_await blocking_executor->run(...)`. Do not move timers, sockets, or
the whole coroutine graph onto the blocking pool.

`run_blocking` suspends the actor task and releases its actor worker, but it
does not release mailbox ownership. Later messages for the same
`actor_id + partition_key` remain FIFO queued. Split independent state domains
into independent partition keys first; other partitions can then progress
while one partition awaits blocking work.

Cancellation prevents an abandoned actor continuation from resuming, but it
cannot preempt an arbitrary synchronous C++ function. Such functions must have
domain-level timeouts where applicable. Their captures, actor object, and actor
library remain alive until already-admitted work retires.

## Minimal runtime setup

```toml
[actor_runtime.scheduler]
policy = "stealing"
workers = 0
blocking_workers = 0
slow_resume_warning_ms = 10

[actor_runtime.routing]
hop_limit = 32

[actors.example]
library = "example"
enabled = true
partition = "source_platform:conversation_id"

[pipelines.message]
source = "obcx::core::events::RawMessageEvent"

[[pipelines.message.stages]]
name = "example"
actor = "example"
input = "obcx::core::events::RawMessageEvent"
output = "obcx::actors::events::ExampleHandled"
mode = "await"
```

## Verification and recovery

Use the complete root suite and `actor_sdk_v2_smoke` before deployment.
Standalone actor repositories run their own release gates. Operational rollback means
deploying the preceding OBCX release together with its matching configuration
and extension binaries; it does not mean switching the actor-only executable
to another runtime path.

`obcx --validate-config <path>` loads mandatory contracts and performs the
production structural and actor-input checks without constructing actors or
starting runtime activity. Executed feedback routes now fail explicitly with
`message_routing_cycle` or `message_routing_hop_limit`; the default hop limit
is 32 and route diagnostics exclude complete payloads.

The `reload` command accepts the request asynchronously. Completion is reported
with attempt/generation ids and stable codes including `reload_busy`,
`reload_parse_failed`, `reload_contract_invalid`,
`reload_dependency_identity_conflict`, `reload_activation_failed`,
`reload_restart_required`, `reload_drain_timeout`, and `reload_shutdown`.
Preparation and drain failures leave the previous generation active. After a
successful but bad actor deployment, restore the preceding immutable actor and
actor-owned configuration set and reload it; restart instead when a bot,
database, or runtime thread-budget definition changed.
